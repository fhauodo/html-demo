EVA 底表取数说明（层级仓 × SKU 库龄）

文档用途：同步 EVA 生产底表结构与取数口径 计算实现：数据组侧（FIFO 等推演逻辑见附录） 更新：2026-08-28

1 文档说明与取数目标

本文面向数据组，说明从 EVA 生产库（eva_wms）抽取逻辑库龄计算所需底表的表结构、关联关系与取值规则。

取数目标：按 「仓库 × 层级仓（private_id）× SKU」 维度，导出层级库存变动流水及初始化快照，供数据组在自有环境完成库龄推演。
边界：整仓逻辑库龄（默认 FIFO）已存在；本次重点是拆到层级仓。具体 FIFO 推演、库龄区间划分等计算逻辑在数据组侧实现，本文附录仅作业务口径参考。
EVA 底表 → 过滤 / 关联 / 回表取时间 → 数据组导出层 → 数据组 FIFO 推演（附录参考）

试点范围（示例）：SPL 仓体系 wh_id ∈ {21, 22, 68, 74, 117}；当前流水主要集中在 wh_id=21（SPL仓），其余子仓可按需扩展。

2 EVA 相关底表概况

算层级库龄，本质上需要两类数据：

  • 起始日各层级仓有多少货 → 来自快照表 t_wms_inventory_private
  • 起始日之后每笔入/出/分配怎么变 → 来自流水表 t_wms_inventory_private_log

其余表都是辅助：给 ID 翻译成名称、给流水补上真实的出入库时间。

一句话理解表关系：以流水表为中心往外连——左边连层级/仓库表拿名称，右边连出入库单拿真实时间；快照表单独取，作为推演起点。

2.0 取数链路（按这个顺序理解）

①
从流水表取「谁、在哪、变了多少」
主表 t_wms_inventory_private_log：每条记录是一次库存变动。关键字段：private_id（哪个层级仓）、wh_id（哪个仓库）、sku、change_qty（±数量）、business_type（入库/出库/分配）。
②
关联层级表 / 仓库表 → 把 ID 翻译成名称
流水.private_id = 层级表.level_id → 得到「分销_FR_SPL」等层级名；流水.wh_id = 仓库表.wh_id → 得到「SPL仓」等仓库名。只是翻译，不产生新数据。
③
用 bound_no 回出入库单 → 取真实业务时间
流水上的 create_time 是系统写账时间，不能用来算库龄。入库流水用 bound_no 关联 t_wms_inbound.inbound_no 取 inbound_time；出库流水关联 t_wms_outbound.outbound_no 取 outbound_time。
④
单独取快照表 → 作为推演起始库存
t_wms_inventory_private 记录某一时点（如 8/30）各层级仓 SKU 的可用/锁定结存，不是变动流水，而是告诉数据组「从这天开始，各层级仓手里有多少货」。

3 流水过滤规则（取数核心）

重要：流水表并非每条记录都代表「真正的入库/出库」。约一半为锁定/释放/冲正等内部转移，不改变库存总量，必须排除，否则结存会被提前扣减。

3.1 四类动作，取数只保留三类

动作判断条件总量变吗是否取
入库 business_type ∈ {2,3,4,6,7,100} 且 in_out_type='1'；调拨入库（3）另须 inventory_type='1' 且 change_qty>0（见 3.5） ✅ 增加 取
出库（真发货） business_type ∈ {-2,-3,-4,-6,-100} 且 in_out_type='2' 且 bound_no 非空 ✅ 减少 取
库存分配 IA business_type='1000' ⚠️ 同仓层级间转移 取（单独查询，见 5.2）
锁定 lock business_type ∈ {-200,-300,-400,-500,-600} ❌ 不变 舍
占用 / 释放 / 冲正 bound_no 为空 ❌ 不变 舍

3.2 business_type 编码对照（SPL 仓生产分布供参考）

business_type含义条数（约）取/舍
-200订单锁定~40,000❌ 舍
-4销售出库~20,000✅ 取（须 bound_no 非空）
-3调拨出库~700✅ 取
-100 / -2 / -6其他/盘点/加工出库少量✅ 取
3调拨入库~4,500✅ 取
4 / 100 / 2 / 6 / 7退货/其他/盘点/加工/移除入库~1,000+✅ 取
1000库存分配 IA~700✅ 取（双流水）
-300 ~ -600其他锁定~300❌ 舍

3.3 为什么出库必须加 bound_no 非空

销售（-4）、调拨（-3）等出库采用「先占用、后发货」两段式，同一类型下多种流水 in_out_type 均可能为 '2'：

阶段inventory_typechange_qtybound_no取/舍
占用·扣可用1（可用）负空❌ 舍
占用·加锁定2（锁定）正空❌ 舍
发货·扣锁定2（锁定）负有值✅ 取
释放·退订2→1负→正空❌ 舍
稳定口径：真出库 = in_out_type='2' 且 bound_no IS NOT NULL AND bound_no <> ''

3.4 直接可用的 WHERE 条件

入库：

WHERE wh_id = 21 AND del_flag = 0 AND in_out_type = '1' AND ( business_type IN ('2','4','6','7','100') OR (business_type = '3' AND inventory_type = '1' AND change_qty > 0) )

出库（真发货）：

WHERE wh_id = 21 AND del_flag = 0 AND business_type IN ('-2','-3','-4','-6','-100') AND in_out_type = '2' AND bound_no IS NOT NULL AND bound_no <> ''

库存分配 IA：

WHERE wh_id = 21 AND del_flag = 0 AND business_type = '1000'

3.5 调拨入库：排除在途配对行

调拨收货（business_type='3'）时，同一 SKU 往往成对写两条流水：在途减少（inventory_type='4'，负向）+ 可用增加（inventory_type='1'，正向）。两条均满足 in_out_type='1'，若不过滤会把在途行误当作入库批次。

inventory_typechange_qty含义取/舍
4（调拨在途）负在途减少，与可用增加配对舍
1（可用）正目的仓可用增加，新批次起点取

生产样本 AS26081200013 / IB260828680：每个 SKU 均为「在途 -N + 可用 +N」配对，入库取数只保留 inventory_type='1' AND change_qty>0 那条。

3.6 自有仓 / 平台仓始发调拨（无源仓出库流水）

业务前提：始发仓为自有仓（wh_type=1）或平台仓时，EVA 将其视为「无限库存、不做本地库存监管」——不写锁定、不写源仓可用/锁定出库流水。库龄取数不应期待在源仓 private_log 里找到 -300 锁定或 -3 真出库（bound_no 有值）记录。

与第三方仓始发的标准四段式（锁定 → 真出库 → 目的在途↑）不同，自有仓始发链路如下：

阶段始发仓（自有/平台）目的仓（第三方）private_log
建发货单不占用、无锁定流水不变通常无
发货无出库流水调拨在途↑（inventory_type=4）仅目的仓；bound_no 常为空
收货—在途↓ + 可用↑（调拨入库 IB）目的仓；按 3.5 取可用+

生产样本 AS26082500007：始发 立讯发货仓（自有仓）→ 目的 筋斗云DWA仓（第三方仓）。流水全部落在目的仓（34 条），特征为 business_type=-3、inventory_type=4、change_qty>0、bound_no 空——这是在途增加，不是源仓出库，现有 bound_no 非空过滤会正确排除，无需额外规则。

库龄推演含义：自有仓始发时，源仓 private 层无出库可取，库龄不在源仓终结；目的仓侧等 IB 收货后按 inbound_time 新起批次（与调拨入库口径一致，不继承源仓）。

对比：第三方仓始发样本 AS26082700002（NAVER_KR → 公共）有完整 -300 锁定 2 条 + -3 真出库 1 条（源仓 inventory_type=2，bound_no=OB260828295）+ 目的在途 1 条（inventory_type=4，正向，不算源仓出库）。

4 业务时间怎么取（不能直接用 create_time）

流水表 create_time 是系统写流水的时刻，通常比真实业务时间晚 15–40 小时，不能用于库龄计算。须通过 bound_no 回标准出入库单取实际时间。
流向business_type取哪个时间来源表关联方式
入库 2/3/4/6/7/100 等 inbound_time t_wms_inbound 流水 bound_no = inbound_no
出库 -2/-3/-4/-6/-100 等 outbound_time t_wms_outbound 流水 bound_no = outbound_no
注意 other 单时间字段：t_wms_other_inbound / t_wms_other_outbound 上有两套时间——other_*_time 是制单时间（不能用），inbound_time / outbound_time 才是实际出入仓时间。建议直接回标准单 t_wms_inbound / t_wms_outbound 取时间，无需关联 other 表。

库存分配（1000）无标准出入库单，时间锚点在数据组推演层处理（附录 A.3 说明继承规则）。

5 参考 SQL 与建议输出字段

5.1 出入库流水 + 层级仓（主查询）

SELECT l.private_id, lv.level_name AS level_name, lv.parent_id, l.wh_id, l.sku_id, l.sku, l.change_qty, l.result_qty, l.business_type, l.inventory_type, l.in_out_type, l.bound_no, l.business_no, l.create_time FROM eva_wms.t_wms_inventory_private_log l LEFT JOIN eva_wms.t_wms_inventory_level lv ON l.private_id = lv.level_id AND lv.del_flag = 0 WHERE l.wh_id = 21 AND l.del_flag = 0 AND ( (l.business_type IN ('2','4','6','7','100') AND l.in_out_type = '1') OR (l.business_type = '3' AND l.in_out_type = '1' AND l.inventory_type = '1' AND l.change_qty > 0) OR (l.business_type IN ('-2','-3','-4','-6','-100') AND l.in_out_type = '2' AND l.bound_no IS NOT NULL AND l.bound_no <> '') ) ORDER BY l.sku, l.private_id, l.create_time;

5.2 库存分配 IA 双流水（单独查）

SELECT l.private_id, l.wh_id, l.sku_id, l.sku, l.change_qty, -- 负=出腿(from)，正=入腿(to) l.business_no, -- 分配单号，出/入同号 l.inventory_type, l.create_time FROM eva_wms.t_wms_inventory_private_log l WHERE l.wh_id = 21 AND l.del_flag = 0 AND l.business_type = '1000' ORDER BY l.business_no, l.change_qty DESC, l.create_time;

一次分配 = 同 business_no 下一条 change_qty<0（from 出）+ 一条 change_qty>0（to 入）。

5.3 起始日库存快照（初始化）

SELECT p.private_id, lv.level_name, p.wh_id, p.sku, p.available_qty, p.booking_qty, p.allocate_onroad_qty FROM eva_wms.t_wms_inventory_private p LEFT JOIN eva_wms.t_wms_inventory_level lv ON p.private_id = lv.level_id AND lv.del_flag = 0 WHERE p.wh_id = 21 AND p.del_flag = 0 AND (p.available_qty > 0 OR p.booking_qty > 0);

6 取数注意事项

① 时间锚点

入库取 inbound_time，出库取 outbound_time；不用流水 create_time。

② IA 单独查

business_type=1000 双流水不在普通过滤里混排，建议单独导出后在推演层合并。

③ 整仓结果复用

整仓逻辑库龄（FIFO）已存在；本取数仅用于层级拆分，不必重算整仓。

④ 不良品

当前 SPL 仓 defect_qty 全为 0，暂不纳入；后续启用再扩展。

⑤ 数据量

SPL 仓流水约 7.5 万条（2025-06 ~ 2026-08），可全量导出。

⑥ 层级改造影响

库存层级改造后树结构会变，但 level_id 可保持不变；取数关联仍以 private_id = level_id 为准。

⑦ 调拨入库过滤

type=3 须加 inventory_type='1' AND change_qty>0，排除在途配对行（见 3.5）。

⑧ 自有仓始发

自有仓/平台仓始发调拨无源仓出库流水，只关注目的仓在途→入库（见 3.6、7.8）。

取数阶段最需验证的两点：
1. 出库过滤是否误含占用/释放（须 bound_no 非空）；
2. IA（1000）双流水是否完整配对（同 business_no 一正一负）。
详见第 7 节生产单据逐项核验结果。

取数结论34 条均 ❌ 舍；等 IB 收货后按 3.5 取可用+入库

✅ 已验证通过

  • 真出库（-4/-3/-100 + bound_no 有值）正确纳入
  • 退货入库（type=4, in_out_type=1）正确纳入

A 附录：库龄计算逻辑参考

本节说明 EVA 侧业务口径，供数据组设计 FIFO 推演时使用。不作为取数强制约束，实现细节由数据组自行决定。

A.1 基本口径

  • 推演维度：仓库 × 层级仓 × SKU × 批次
  • 库龄天数 = 目标日 − 批次入库日（用业务时间 biz_time）
  • 出库按 FIFO：先消耗最早入库的批次
  • 起始日快照作为各层级 FIFO 队列初始批次（批次日期可用起始日前一天近似）

A.2 业务操作与库龄后果（对照表）

业务操作business_type库龄后果（推演层）
采购/盘点/退货/维修/加工/移除/其他入库1/2/4/5/6/7/100新起批次，从 inbound_time 计龄
调拨入库3新起批次，按目标仓到货日计龄（不继承源仓）
销售/调拨/盘点/加工/其他出库-4/-3/-2/-6/-100FIFO 消耗最老批次
库存分配 IA1000继承库龄（唯一继承场景）

A.3 库存分配 IA —— 唯一继承库龄的场景

同仓内层级 A → 层级 B 转移，货物理未动，仅改记账层级。若按分配日重新计龄，旧库存库龄会被「洗白」。

【出腿】business_type=1000, change_qty<0, private_id=A → A 层级 FIFO 消耗最老批次，按 business_no 缓存消耗批次及日期 【入腿】business_type=1000, change_qty>0, private_id=B → B 层级新增批次，日期照抄出腿消耗的批次日期（非分配日）

A.4 调拨为什么不继承

调拨（-3/3）是跨仓搬运：源仓出库终结该批次库龄，目标仓按 inbound_time 新起批次。与 IA（1000）同仓改标签不同，不要混用继承逻辑。

自有仓始发例外：始发为自有仓/平台仓时源仓无 private 出库流水（见正文 3.6），库龄只在目的仓侧从 IB 收货日起算；不存在源仓 FIFO 扣减。

A.5 FIFO 推演伪代码（参考）

// batch_queue: Map<(wh_id, private_id, sku), Deque<Batch>> // assign_consumed: Map<business_no, [批次]> FOR EACH doc IN docs ORDER BY biz_time ASC: IF doc.business_type == '1000': IF doc.change_qty < 0: assign_consumed[doc.business_no] = FIFO_deduct(from_key, |qty|) ELSE: push cached batches to to_key (inherit dates) ELSE IF doc.in_out_type == '1': batch_queue[key].push({date: inbound_time, qty: change_qty}) ELSE IF doc.in_out_type == '2' AND bound_no 非空: FIFO_deduct(key, |change_qty|) // aging = 目标日 − batch.date

A.7 推演阶段关键风险

风险1：误把 IA（1000）当普通出库+入库 → 库龄被洗白。须识别双流水继承关系。
风险2：占用/释放混入真出库 → 须在上游取数已用 bound_no 非空过滤；推演层勿重复扣减。
风险3：初始快照批次日期为近似值（起始日前一天），对 180 天+ 长库龄分类影响有限。
